# M6a 衍生品风险案例基础管线设计

## 范围

本切片实现 M6a 的第一段可运行纵向能力：独立数据库契约、上交所官方监管文件适配器、衍生品风险相关性闸门、幂等候选入库、运行快照和独立 GitHub Actions。现有公告、年报和前端均不修改。

深交所、证监会/派出机构适配器以及 LLM 案例抽取在后续切片接入相同接口与表结构；候选文档在相关性和证据验收前不得成为正式风险案例。

## 数据契约

- `risk_source_documents` 保存官方来源文档及采集状态，主键为 `来源:官方文档ID`。
- `derivative_risk_cases` 保存经模型与程序回验后的正式案例，使用公司、事件日期和风险类型构造稳定 `case_key`。
- `risk_case_documents` 维护案例与问询、回复、处分、整改等多份文件的关系。
- `risk_case_evidence` 保存字段级原文、页码/段落和回验状态。
- 四表均启用 RLS；anon/authenticated 只读，service_role 写入。前端当前不读取这些表。

## 上交所来源

使用上交所官网页面自身调用的公开 `commonSoaQuery.do` 接口：

- 监管问询栏目：`channelId=10743,10744,10012`
- 监管措施栏目：`channelId=10007,10008,10009,10010`
- `sqlId=BS_KCB_GGLL_NEW`

适配器负责分页、日期范围、礼貌限速、JSONP 解包、URL 规范化和字段归一，不负责业务判断。

## 相关性闸门

1. 候选召回：标题或正文出现期货、期权、远期、掉期、互换、衍生品、套期保值、保证金等词。
2. 正式相关：衍生品业务词与损失、越权、投机、内控、违规、处罚、追责、风险敞口、保证金不足等风险信号在同一文本窗口内共现。
3. 仅出现法律名称、通用会计政策或普通经营风险，不进入正式案例。
4. 首轮只写 `risk_source_documents`；正式案例表必须等 LLM 结构化结果及原文回验通过后写入。

## 失败与幂等

- 来源文档按 `source_doc_id` upsert，重复运行不重复入库。
- 下载或解析失败写入 `failed` 和异常摘要，后续显式重试。
- 原始官方 URL、文档 ID、接口元数据和运行快照必须保留。
- 工作流独立使用 `risk-sources` 并发锁，不占用公告/年报的 `cninfo` 锁；模型抽取接入后另设批次上限。

## 验收

- 迁移结构、约束、RLS 与权限通过 SQL 检查。
- 适配器使用固定 JSONP 样本完成离线单元测试，并用上交所真实接口完成只读探针。
- 闸门覆盖明确相关、通用政策误命中、仅法律名称和无关文档。
- dry-run 能生成候选快照；write 模式可幂等写入候选表。
