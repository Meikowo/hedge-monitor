# 风险案例监控工作区设计

## 目标

在现有 GitHub Pages 研究终端左侧新增独立的“风险案例监控”工作区，把公告中的计划、
定期报告中的实际和监管文件中的风险后果串成三层研究链条。页面保持现有浅色、克制、
高信息密度的视觉语言，不改变“套保事件”“公告原流”和“计划与实际”的数据结构。

本功能分两阶段交付：先制作使用固定样例数据的本地 Demo，确认表格、筛选和详情结构；
正式风险案例达到上线质量闸门后，再接入 Supabase 并开放线上导航入口。

## 数据边界

- 公开工作区只读取 `derivative_risk_cases`、`risk_case_documents`、
  `risk_case_evidence` 和 `risk_source_documents` 中已形成官方证据链的正式案例。
- 私有 `risk_media_leads` 与 `risk_media_backfill_windows` 只用于研究线索发现，不能被
  anon 前端请求，也不能在公开表格、统计数量或 CSV 中出现。
- Tavily 新闻不能独立证明案例。新闻线索必须反查到交易所、证监会、派出机构、公司公告
  或其他权威原始文件，经过相关性判定、结构化抽取和引文回验后才能成为正式案例。
- 页面不生成综合风险评分，不把监管事实扩展为法律定性，不展示无来源的推测性结论。

## 导航与页面结构

左侧工作区顺序固定为：

1. 数据看板
2. 套保事件
3. 公告原流
4. 计划与实际
5. 风险案例监控

“风险案例监控”右侧数量只统计正式案例。页面主体由四部分组成：

1. 顶部紧凑指标：正式案例数、涉及公司数、重大损失案例数、监管措施/处罚案例数；
2. 筛选栏：关键词、年份、风险类型、来源机构、工具/品种、案例状态；
3. 高密度主表；
4. 按需打开的右侧证据详情抽屉。

主表默认按事件日期倒序，列为：事件日期、公司、风险类型、工具/品种、损失或涉案金额、
监管措施、结果、来源机构、案例状态、证据状态。金额保留原币种和原单位；缺失值显示
“未披露”，不能显示为 0。

## 详情与文档链

点击表格行后，右侧抽屉展示：

- 公司、事件日期、风险类型和事实摘要；
- 涉及工具、品种、金额、监管措施、整改或追责结果；
- 按时间排序的“问询—回复—监管措施/处罚—整改”文档链；
- 每个关键字段对应的页码、原文引文、回验状态和官方原文链接。

桌面端抽屉保持主表可见；移动端改为全屏详情面板。关闭详情后保留原筛选、滚动和选中状态。

## 筛选、导出与状态

- 搜索匹配公司名称、代码、摘要、品种、工具和监管结论；多个筛选条件采用交集。
- CSV 导出完整的当前筛选结果，不受当前屏幕可见行或分页限制，使用 UTF-8 BOM。
- 导出字段包含主表字段以及案例键、币种、单位、置信度、复核标记、官方文档标题、
  文档日期、官方 URL 和证据状态；不导出媒体候选或模型原始响应。
- 页面具有明确的加载进度、空结果、请求超时、有限重试和最终错误状态，不允许永久转圈。
- 数据库没有正式案例时，本地 Demo 仍可展示固定样例；生产导航在上线闸门前保持隐藏。

## 前端边界

- 本地 Demo 放在 `web-demo/risk-cases/`，不访问生产数据库。
- 正式接入时新增独立 `web/risk.js`，负责风险数据读取、标准化、筛选、表格、详情和导出；
  `web/app.js` 只负责共享 shell、导航和视图切换，避免继续膨胀。
- 正式页面复用现有 CSS token、按钮、表格、状态面板和右侧抽屉行为，仅增加风险工作区
  必需的样式，不引入框架或第三方运行时依赖。
- 现有数据看板、套保事件、公告原流和计划与实际四个视图的读取、筛选、导出和移动端
  行为必须保持不变。

## 上线质量闸门

线上入口只有同时满足以下条件才开放：

1. M6a 已形成至少 50 份真正的衍生品风险官方候选文档；
2. 分层人工抽检确认候选相关性精确率不低于 90%；
3. 至少 10 个正式案例完成入库；
4. 每个正式案例至少关联一份官方来源文档，所有前端展示的关键结论都有已回验引文；
5. 媒体候选表继续保持私有，公开 anon 请求无法读取；
6. 风险工作区结构测试、数据转换测试、CSV 测试、真实公开 API 启动测试和移动端检查通过。

在达到闸门前，只交付本地 Demo，不向生产导航添加空入口。

## 测试与回退

- 结构测试验证导航、筛选、主表、空状态、错误状态和详情抽屉引用节点完整；
- 单元测试覆盖金额原单位保留、null 与 0 区分、数组字段、文档链排序、筛选交集和 CSV；
- 公开 API 测试验证正式四表可读、私有媒体表不可读，且初始化在限定时间内结束；
- 回归测试确认公告事件与计划实际页面节点、资源版本和导出行为不变；
- 发布前记录 `main` 基线。若上线异常，使用反向提交恢复前端，不强推，不回滚或删除
  已写入的风险案例数据。
