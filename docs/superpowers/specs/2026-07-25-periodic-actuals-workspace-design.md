# 定期报告实际情况与套期会计工作区设计

日期：2026-07-25  
状态：用户已确认，Demo 已按 2026-07-26 反馈修订  
对应里程碑：M4a、M4b、M5

## 1. 目标与边界

本阶段建立独立于公告事件库的「定期报告实际情况」数据域，并在前端增加独立的「计划与实际」工作区。它回答：

1. 公司在某一报告期实际开展了哪些衍生品业务；
2. 报告期交易流量、期末公允价值和损益分别是多少；
3. 公司是否应用套期会计，应用何种方法；未应用时是否披露原因；
4. 公告中的计划与定期报告中的实际在品种、模式和可比数值上是否一致。

本阶段不修改 `companies`、`hedge_events`、现有公告页面及其数据契约，不把定期报告字段塞入公司静态维表，也不因定期报告缺少披露而推断公司没有开展业务。

## 2. 架构决策

采用「报告级摘要 + 业务级明细」两层模型。

- `periodic_derivatives`：一份报告一条摘要，保存披露状态、报告级套期会计结论、质量状态及报告级证据。
- `periodic_metric_items`：保存原文数值事实。损益、交易流量、公允价值资产和负债使用互不混淆的指标类型。
- `periodic_hedge_accounting_items`：按业务范围或工具保存套期会计明细，允许同一公司同一报告期存在混合应用。
- 未来 M5 的匹配结果使用独立派生表或只读视图，不回写公告事实或定期报告事实。

`companies` 只继续保存名称、代码、行业、企业性质、地区等相对稳定属性。套期会计是随报告期变化的会计事实，不进入公司维表。

## 3. 套期会计数据契约

### 3.1 报告级摘要

`periodic_derivatives` 增加或明确以下字段：

- `hedge_accounting_status`：
  - `已应用`
  - `未应用`
  - `混合应用`
  - `未明确披露`
  - `需复核`
- `hedge_accounting_types`：闭集数组，可取：
  - `公允价值套期`
  - `现金流量套期`
  - `境外经营净投资套期`
  - `其他`
- `non_application_reason`：可空文本。空值表示原文未披露原因，不得显示为“无原因”。
- `hedge_accounting_page`、`hedge_accounting_quote`、`hedge_accounting_quote_verified`：报告级结论证据。

### 3.2 业务级明细

新表 `periodic_hedge_accounting_items` 至少包含：

- `report_id`
- `scope`：商品、外汇、利率、综合或未明确
- `instrument`：期货、期权、远期、掉期、互换或未明确
- `underlying_asset`
- `application_status`：已应用、未应用、未明确披露、需复核
- `accounting_type`
- `non_application_reason`
- `source_section`
- `page`
- `quote`
- `quote_verified`
- `confidence`
- `need_review`

同一报告允许多条明细。例如外汇远期应用现金流量套期，而商品期货未应用套期会计时，报告摘要为 `混合应用`，明细分别记录。

### 3.3 认定规则

1. 年报/半年报中“适用/不适用”勾选或明确陈述为最高优先级证据。
2. 套期会计政策、套期储备、其他综合收益重分类等附注是补充证据，不得仅凭出现衍生品或其他综合收益就推定应用套期会计。
3. 明确“不适用”但没有解释原因时，记录 `未应用 + non_application_reason=null`，前端显示“未披露原因”。
4. 不同章节结论冲突时记录 `需复核`，不得自动选择一个结论。
5. 晶科能源 2025 年报样本应记录为：`未应用`、类型为空、未应用原因为空；不能推断为“不符合条件”或“套期无效”。

## 4. 数值口径重构

停止把 `period_pnl` 解释成“已实现损益”。定期报告数值事实采用明确指标类型：

- `reported_derivative_comprehensive_pnl`：公司披露的衍生品综合损益，可能同时包含已实现、未实现或浮动损益。
- `derivative_disposal_investment_income`：处置衍生金融工具取得的投资收益。
- `derivative_fv_change_pnl`：衍生金融工具产生的公允价值变动损益。
- `period_purchase_amount`
- `period_sale_amount`
- `margin_balance`
- `margin_account`
- `margin_is_restricted`
- `derivative_asset_fv`
- `derivative_liability_fv`
- `derivative_net_fv`
- `opening_book_value`
- `ending_book_value`
- `pct_net_assets`

每条事实保留原币种、原单位、原始数字文本、页码、引文和两个回验标志。购买额、出售额属于交易流量，不作为授权额度、名义本金或期末业务规模。

保证金事实还必须保留报告日、列示科目、受限状态、业务范围和对手方（若披露）。同一余额在其他货币资金、其他应收款或受限资金等多处重复列示时只生成一项事实，并关联多条证据。

晶科能源 2025 年报样本的关键核对：

- 综合损益：`-3,474.88 万元`
- 处置衍生金融工具投资收益：`23,929,647.46 元`
- 衍生金融工具公允价值变动损益：`-58,678,398.34 元`
- 二者合计：`-34,748,750.88 元 = -3,474.875088 万元`
- 衍生金融资产：`58,922,522.23 元`
- 衍生金融负债：`56,128,746.61 元`
- 净额：`2,793,775.62 元 = 279.377562 万元`

## 5. 表格解析与证据回验

复杂表格不得只依赖 PDF 扁平文本。解析流程为：

1. 关键词和目录定位候选页；
2. 保留页面、表格、行、列和单元格坐标；
3. 将结构化单元格及必要上下文送入抽取；
4. 数值回验原始数字文本；
5. 引文回验对应表头、行名和单元格位置；
6. 执行确定性勾稽检查；
7. 未通过双回验的关键数值仅进入复核队列，不进入汇总、图表或 M5 匹配。

确定性检查至少包括：

- 分项购入额之和与合计购入额；
- 分项售出额之和与合计售出额；
- 分项综合损益之和与合计综合损益；
- 衍生金融资产减衍生金融负债与期末净账面价值；
- 处置投资收益加公允价值变动损益与公司披露综合损益（仅在原文口径吻合时）。

程序不能为了通过勾稽而改写原始值。勾稽失败只标记 `need_review=true`。

## 6. 前端信息架构

现有侧栏保留：

- 数据看板
- 套保事件
- 公告原流

新增独立入口：

- 计划与实际

「套期会计」不是独立顶级工作区，而是「计划与实际」中的核心研究维度。

### 6.1 主表

一行表示：`公司 × 报告期 × 套保类别`。

默认列：

- 报告期
- 公司
- 类别 / 品种
- 公告计划额度及口径
- 实际交易流量
- 期末保证金
- 衍生金融资产
- 衍生金融负债
- 公允价值净额
- 衍生品综合损益
- 已实现处置投资收益
- 公允价值变动损益
- 套期会计状态
- 套期会计方法
- 匹配状态
- 证据完整度

提供年份、报告类型、类别、套期会计状态、匹配状态、企业性质、行业和地区筛选。默认只让双回验通过的数值进入主表统计；待复核值在详情中显示但明确标记。

### 6.2 右侧详情抽屉

详情按四组展示：

1. 公告计划：授权额度、口径、工具、品种、期间与公告证据；
2. 定期报告实际：购入/售出、期末资产/负债/净额、损益拆分及勾稽结果；
3. 套期会计：报告级结论、业务级明细、方法、未应用原因与原文证据；
4. 核对结果：品种、模式、数值三维状态及“为什么不可比”。

每个数字都能回到页码和原文。`null` 显示“未披露”，不得显示为 0。

### 6.3 本地 Demo 范围

先在 `web-demo/periodic-actuals/` 建立独立静态 Demo：

- 使用固定样例数据，不连接 Supabase；
- 复用现有浅色、细边界、高密度研究终端风格；
- 展示侧栏入口、主表、筛选条和右侧详情抽屉；
- 使用晶科能源样例展示损益拆分、套期会计未应用和证据状态；
- 不覆盖 `web/`，不参与 GitHub Pages 部署；
- 用户确认结构后，再将交互和真实数据接入拆成正式实施任务。

## 7. 错误与异常状态

- 报告未披露衍生品：主表显示“明确未披露”。
- 找到相关章节但字段缺失：字段显示“未披露”，不填 0。
- 解析失败：报告进入“抽取失败/待重试”，不产生半成品事实。
- 数字通过、引文失败：显示“待证据复核”，不进入统计和匹配。
- 套期会计章节冲突：显示“需复核”，保留两处证据。
- 公告计划与实际口径不同：显示“口径不可比”，不得计算占用率。

## 9. 发布与回退

### 9.1 代码回退

- Demo 在独立目录，不修改生产 `web/`，删除该目录即可完全撤销。
- 正式接入时使用独立 Git 分支和原子提交；合并前记录当前 `main` 提交 SHA。
- 发布异常时优先对问题提交执行 `git revert <sha>`，产生可审计的反向提交；不强推、不改写历史。
- 在每次正式发布前创建可读标签，例如 `frontend-m3-stable-20260725`。

### 9.2 数据库回退

- 每个迁移同时提供向前迁移和明确的回退 SQL；
- 新字段先保持可空，新表先旁路写入，前端切换前不删除旧字段；
- 破坏性字段删除至少跨一个稳定版本，不在首次接入时执行；
- 数据回填前导出受影响表或创建快照表；回滚只删除本次新增对象或恢复快照。

### 9.3 部署回退

- GitHub Pages 只从已提交版本部署；
- 若新页面故障，revert 对应提交并重新运行 Pages workflow；
- Supabase 数据契约采用向后兼容变更，使旧前端在数据库升级后仍可继续读取。

## 10. 非目标

- Demo 阶段不实现真实数据库查询、M5 自动匹配、CSV 导出或生产路由。
- 本阶段不开发衍生品风险案例前端。
- 不把未验证的定期报告数值混入现有公告事件统计。
- 不改变当前 GitHub Pages 线上版本。

## 11. 2026-07-26 Demo 修订

1. 一行仍表示「公司 × 报告期 × 套保类别」。同一报告同时披露商品和外汇业务时必须拆行，不能把公司合计事实塞入其中一个类别。

3. 处置投资收益、公允价值变动损益、衍生金融资产和负债只在年报附注中披露公司合计，不能分摊到商品或外汇。主表分类行显示「报告级合计」提示，详情抽屉展示合计数值及勾稽式。

## 12. 2026-07-26 期末资产负债与保证金修订

1. 主表将原“期末公允价值净额”拆为“衍生金融资产、衍生金融负债、公允价值净额”三列，并在其前新增“期末保证金”。总额资产与负债是独立风险事实，净额只用于勾稽，不能替代总额。
2. 一行仍表示「公司 × 报告期 × 套保类别」。分类资产或负债未披露、但报告附注存在公司合计时，分类行显示“报告级合计”，数值只在详情中的报告级区块出现且不参与分类汇总。
3. 保证金没有原文证据时显示“未披露”，不得从交易流量、公允价值或公告额度推算。
4. 公告“保证金最高占用额”与年报期末保证金余额只做 B 级时点核验；报告日余额低于上限不能证明期间内未超限。只有年报明确披露期间最高保证金时才可做 A 级核验。
5. 保证金与名义本金、业务总额、合约价值等不同口径不得直接比较。科目包含非衍生品保证金且无法拆分时标记“需复核”。
