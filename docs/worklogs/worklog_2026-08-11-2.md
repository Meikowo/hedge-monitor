# 2026-08-11 M6a 首批官方风险案例纵向切片

## 本阶段目标

在不增加新的 LLM 调用、不修改数据库结构和不手工录入案例的前提下，将现有巨潮官方公告
转为第一批可在正式风险案例工作区展示、可回到页级原文核验的官方案例。

## 实施结果

- 新增 `scripts/publish_official_risk_cases.py`：从 `announcements + extractions` 读取既有
  结构化公告，执行“实际发生损失”确定性闸门，再下载入选 PDF 对引文逐字定位。
- 拒绝管理制度阈值、假设性风险、明确未发生损失及普通汇兑损失；精确金额只在官方原文
  可直接解析时写入，不能确认时保持空值。
- 使用 `<code>|<ann_date>|重大衍生品损失|official` 作为稳定案例键，四表按来源、案例、关系、
  证据顺序幂等写入；重复运行不会生成重复案例或重复证据。
- 首批入库 3 个官方案例：
  - 江特电机，2025-12-25，实际衍生品损失达到重大标准，官方原文未披露精确金额；
  - 豪森智能，2025-10-31，衍生品损失 1,268.39 万元；
  - 天宇股份，2024-03-07，衍生品损失 1,549.80 万元。
- 官方四表完整性：3 份来源文档、3 个案例、3 条案例—文档关系、3 条已完成引文与数值
  回验的证据。江特电机媒体记录已标记为 `officially_corroborated` 并关联官方案例，前端
  不重复计数。
- 新增 `.github/workflows/risk-official.yml`：北京时间每日 09:35 自动发布最多 3 个案例；
  手动写模式仍需 `write=true` 和 `I_UNDERSTAND`。该工作流不使用 Tavily 或 MiniMax。

## 验证

- `python -m unittest discover -s tests -p "test_*.py"`：200 项通过。
- 7 组离线 Node 前端结构／逻辑测试全部通过。
- 真实公开 API：风险工作区读取 3 个官方案例、2 条媒体记录、2 个媒体来源；主站读取
  9,221 个事件和 20,546 条结构化公告。
- Supabase Security Advisor：0 项；未改 schema、RLS 或浏览器权限。
- 发布范围不包含 `.env`、`output/`、PDF 或任何密钥值。

## 发布与回退

- 本阶段提交信息为 `Publish verified official risk cases`，通过 GitHub 插件非强制快进到
  `main`；发布时会再次核对远端父提交，基线变化时停止而不强推。
- 如需整体回退，基于本阶段发布前的 `main` 提交创建反向提交；不得重写 `main` 历史。
