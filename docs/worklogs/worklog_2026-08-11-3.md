# 2026-08-11 M6a 交易所官方来源双轨扩展

## 本阶段目标

在不修改数据库结构、不调用 LLM、也不把候选自动升级为正式案例的前提下，同时推进两条线路：发布剩余两个已通过巨潮 PDF 原文核验的官方案例；建立上交所与深交所官方监管文档的定时增量候选采集。

## 本地实施结果

- 正式案例发布器改为先读取 `risk_source_documents.source_doc_id`，排除已发布的 `cninfo:<ann_id>` 后再应用批次上限。原有 3 个案例不会继续占满每日批次；没有新案例时生成空快照并正常结束，未发布候选全部 PDF 回验失败时仍保持硬失败。
- 新增 `scripts/risk_sources/szse.py`。真实调试确认深交所列表页是 JavaScript 外壳，数据来自官网 `/api/report/ShowReport/data`；问询函、监管措施、纪律处分分别使用官网目录 `main_wxhj`、`1800_jgxxgk`、`1800_jgxxgk_cf`，原文限定到 `https://reportdocs.static.szse.cn`。
- `scripts/fetch_risk_documents.py` 支持 `--source sse|szse|all`，按来源隔离失败，正文读取失败写为 `failed`，并保留来源级 CSV 与状态计数。交易所候选仅进入 `risk_source_documents`。
- `.github/workflows/risk-poc.yml` 改名为 `Collect Official Risk Sources`：每天 UTC 02:10（北京时间 10:10）自动采集最近 30 天，来源为 `all`、正文读取和数据库写入开启；手工运行默认 dry-run，写入必须双确认。
- `web/risk.js` 只读取 `status=extracted` 的正式官方文档，保持现有列表、详情、筛选、媒体层和 CSV 字段不变。
