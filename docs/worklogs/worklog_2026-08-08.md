# Worklog 2026-08-08

## 本阶段目标

将“计划与实际”从 119 家验证/优先样本推进到自动运行的 2025 年正式数据库。用户确认第一
阶段只处理 2025 年套保事件公司，完成后再评估“年报披露衍生品但当年没有套保公告”的补充池。

## 数据基线复核

- `hedge_events.anchor_year=2025`：2,015 个事件、1,812 家公司。
- 2025 年年报表：119 条 `extracted`、1 条 `failed`、1 条 `skipped`。
- 正式 1,812 家与既有 119 家已提取公司的交集为 108 家；其余 11 家既有结果继续保留展示，
  但不进入本轮进度分母。
- 唯一已知失败为南钢股份 600282，report_id `1225011770`，原因是模型 JSON 不完整。

## 已完成实现

- 新增正式池生成器和静态快照。真实生成结果为 1,812 行、1,812 个唯一代码、无空代码。
- 修正早期 POC 的范围假设：正式池含 18 家 B 股公司，44 家公司主表记录缺失。元数据写入
  前会幂等补齐缺失公司的最小主表记录，避免外键阻塞，同时不缩小固定分母。
- 新增公司级进度脚本，按公司合并旧版/修订版报告状态，区分已发现、待定位、已定位、
  已提取、跳过、失败、需 OCR、待发现、人工接受和核验率。
- 真实进度读取：目标 1,812，已发现 109，已提取 108，失败 1，待发现 1,703，人工接受 6。
- 提取批次新增单份失败隔离和 3 次失败熔断。少量失败不阻塞同批后续报告；第三次失败后
  停止剩余模型调用并保留部分成功结果。
- GitHub Actions 已在本地改为正式池：每 6 小时全市场发现元数据、定位 48、提取 18，
  前后输出进度；手动模式新增 `formal1812` 和可选 `report_id`。
- 独立代码审查发现单次 full 查询存在巨潮 300 页静默截断风险。现改为按季度四窗口扫描，
  任一窗口达到上限仍有结果时自动按日期二分，最小到单日后才明确失败；不再重复扫描同一个
  被截断的年度前缀。
- 审查同时补齐三项保护：已提取/人工接受旧版不会因发现修订版而自动隐藏；核验数量按规范
  报告公司去重；手动 `report_id` 仅接受单个数字 ID，拒绝逗号和过滤表达式。
