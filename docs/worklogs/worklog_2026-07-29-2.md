# Worklog 2026-07-29-2

## M4 年报定时自动批处理

- `.github/workflows/periodic-poc.yml` 增加每 6 小时定时触发：
  - UTC：`22:45、04:45、10:45、16:45`；
  - 北京时间：`06:45、12:45、18:45、00:45`。
- 定时批次固定使用 120 家 2025 年优先池：
  - 每轮定位最多 12 份 `discovered` 年报；
  - 每轮抽取最多 6 份 `located` 年报；
  - 无待处理数据时正常空跑。
- 定位和抽取均显式限定 `fiscal_year=2025`、`report_type=annual`，不会越界读取同一公司
  其他年度或半年报。
- 保留 metadata、locate、extract 手动入口和原样本集选项；手动 LLM 抽取仍需勾选
  `confirm_llm`。
- 支持仓库变量 `PERIODIC_AUTO_ENABLED=false` 暂停自动任务；默认无需配置变量即启用。

## 失败隔离

- 定位器默认不再自动包含 `failed`，防止下载失败报告反复进入队列。
- 手动 locate 新增 `retry_failed`，只有明确勾选后才重试失败报告。
- 单份报告发生 PDF 下载、模型响应、解析或数据库写入异常时，非 dry-run 将报告状态
  写为 `failed` 并记录最多 500 字符的异常摘要；随后让当前工作流失败停止。
- 定位和完整抽取在 PDF/LLM 调用前先持久化领取为 `failed`。runner 超时、被终止或
  隔离说明更新失败时，领取状态仍能阻止下一轮自动重试。
- 后续定时任务跳过该报告，已完成报告和 `review_status=accepted` 人工金标准不受影响。
- 既有多表 PostgREST 写入不是单事务；安全边界由状态控制：前端只把 `extracted`
  报告构建为展示行，中断后的部分结果保持隐藏，人工重试时按既有替换规则重建。本轮
  不扩展数据库 RPC。
- 高级 CLI 的选择性 `--pass` 重跑也会先领取并隐藏，成功后恢复原报告状态；失败快照
  和隔离说明分别尽力写入，不会因其中一个写入失败而遮蔽原始异常。

## 用户操作

- 发布后不需要手动点击，下一次定时点会自动启动。
- 若某次工作流显示失败，先不要反复点击；检查被隔离报告后，再手动选择 locate 并勾选
  `retry_failed`。
- 若需暂停，在 GitHub 仓库 Actions variables 中设置
  `PERIODIC_AUTO_ENABLED=false`；删除该变量或改为其他值即可恢复。
