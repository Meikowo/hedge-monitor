# 工作日志 2026-07-25

## 本阶段主题

确定「衍生品风险案例监测」的产品边界、数据形态、自动化原则，以及它与 M4 年报分析的并行开发方式。

## 已确认决策

1. 风险监测采用独立的风险案例库，共享 `companies` 公司主表，但不混入公告事件表或定期报告事实表。
2. 只收录与上市公司期货、期权、远期、掉期、互换、衍生品或套期保值业务直接相关的风险；一般负面新闻、普通问询和无衍生品证据的处罚不纳入。
3. 数据来源优先采用官方材料：
   - 交易所问询、监管函、纪律处分等；
   - 证监会及派出机构行政处罚、监管措施等；
   - 上市公司披露的衍生品损失、整改或风险事件公告；
   - 能回溯到权威原始材料的重大历史衍生品案例。
4. 首版不采用逐条手工录入。自动流程为：
   `官方来源发现 → 关键词召回 → 衍生品相关性闸门 → 结构化抽取 → 原文证据回验 → 去重/upsert`。
5. 人工只负责抽样质量验收，不负责维持日常数据供给。手工补充/纠错接口仅列为后期可选，并需保留来源和修改审计记录。
6. 风险类型首版闭集：超授权/未经授权、偏离套保目的、重大衍生品损失、保证金与流动性风险、审批/内控缺陷、衍生品会计与披露违规、授权要素不一致、监管整改/处罚/追责。

## 并行开发结论

M4 年报/半年报分析与 M6 风险案例可以同步开发，因为两者的来源、事实表、抽取脚本和调度工作流彼此独立。

允许并行的部分：

- 数据库表设计与各自迁移；
- 来源采集适配器；
- 文档定位、结构化抽取与证据回验；
- 独立测试与 Actions 工作流。

需要统一协调的部分：

- 共用 `companies` 公司主表及公司代码映射；
- 数据库迁移编号和公共字段规范；
- Supabase 容量/请求与 MiniMax 套餐额度；
- 前端路由、共享筛选器和公司详情页。

为减少冲突，两个数据管线稳定前不并行修改同一前端核心文件。先分别验收数据契约，再依次接入风险案例工作区与公司详情时间线。
